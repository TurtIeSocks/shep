### lib/God.js — 632 LOC [COMPLEX]
Daemon-side root. Builds `God` singleton: `next_id`, `clusters_db` (proc registry, plain object keyed by pm_id, also `_old_<id>` string keys during reload), `bus` (EventEmitter2, wildcard, maxListeners 1000). At module load: `cluster.setupMaster({exec: ProcessContainer[Bun].js})` — the cluster-mode injection point. Mixes in Event/Methods/ForkMode/ClusterMode/Reload/ActionMethods/Watcher, then `God.init()` (starts Worker.js after 500ms, loads config).
- `prepare(env,cb)`: entry from RPC. UUID per proc. No `instances` → single: if STOPPED status registers stub (no spawn); else `executeApp`. With `instances`: 0→numCPUs, <0→numCPUs+n, ≤0→1; serial `timesLimit(n,1)` spawn; per-instance `injectVariables`.
- `executeApp(env,cb)` (~220 lines, deep callback nesting): clone env, flatten `env.env` into copy, status=LAUNCHING (or STOPPED if !autostart). First-time (pm_id undefined): assign pm_id, zero restart counters, suffix pid file `-<pm_id>.pid`, suffix log files unless `merge_logs`, `God.watch.enable` if watch. `registerCron`. autostart=false → stub `{process:{pid:0}}`. Then branch: cluster_mode → `nodeApp` + wire `error/disconnect/exit/online` events, wait_ready gate (bus listener for `{raw:'ready'}` packet with listen_timeout fallback 3000ms), Bun hack: 500ms timer force-online (Bun cluster emits no 'online' for non-listening apps); fork → `forkMode` + `exit` handler, same wait_ready gate. `readyCb`: findPackageVersion, optional vizion git parse (`ENABLE_GIT_PARSING`, default off), status→ONLINE, notify.
- `handleExit(clu, code, signal)`: THE restart/backoff brain (traced below in verdicts).
- `injectVariables`: computes `NODE_APP_INSTANCE` (or custom `instance_var`/`PM2_PROCESS_INSTANCE_VAR`) = lowest free slot among same-name procs; `increment_var` support (max+1).
- `finalizeProcedure`: vizion.analyze walking up dirs for git metadata.
- `writeExitSeparator`: DEAD — both call sites commented out; would also truncate logs (writeFileSync not append).

### lib/God/Methods.js — 278 LOC
Registry helpers + kill machinery. `getFormatedProcesses` skips `_old_` entries (isNaN pm_id). `findByName`: name, resolved exec path, or 'all'. `checkProcess(pid)`: `kill(pid,0)`. `processIsDead(pid, env, cb, sigkill)`: polls `_tree_pids||[pid]` every `kill_retry_time` (schema default 100ms); after `kill_timeout` (1600ms default) SIGKILLs survivors and recurses once with sigkill=true; second timeout → `{type:'timeout'}` error. `killProcess(pid, env, cb)`: if `KILL_USE_MESSAGE`/`shutdown_with_message` → IPC `'shutdown'` message instead of signal; else if !treekill → single `kill(pid, KILL_SIGNAL)` (default SIGINT); else `treekill()`, stores returned pid list in `pm2_env._tree_pids` for the death poll. `getNewId`: monotonic counter (reset to 0 when db empties — in ActionMethods). `resetState`: created_at=now, unstable_restarts=0, prev_restart_delay=0 (backoff reset on manual restart/reload).

### lib/God/Reload.js — 240 LOC
0-downtime reload, cluster_mode+ONLINE only (else falls through to `restartProcessId`). Both paths: move old worker to `clusters_db['_old_<id>']`, clone env, `resetState`, restart_time++, `executeApp(new_env)`.
- `hardReload` (via `reloadProcessId`): wait for new worker — `wait_ready` set → bus `'ready'` packet, else cluster `'listening'` event; then `deleteProcessId('_old_<id>')` (stop+kill old). Timeout `listen_timeout||3000` → kill old anyway (`readySignalSent` guard).
- `softReload` (via `softReloadProcessId`, requires !wait_ready): wait new `'listening'` → send `'shutdown'` IPC msg to old worker → wait old `'disconnect'` → delete; `GRACEFUL_TIMEOUT` (8000) force-delete fallback. Old worker drains in-flight requests.
Zero-downtime window exists ONLY because Node cluster master holds the listening socket and both old+new workers accept during overlap.

## Flags

- **Dead code**: `God.writeExitSeparator` (both call sites commented; would truncate logs via writeFileSync if re-enabled); `God.watch.disableAll` never called AND crashes (`Array.splice` on plain object)
- **Live bugs worth not porting**: ActionMethods stopWatch/toggleWatch/startWatch ProcessName branches index `clusters_db` with an array (findByName result) → silent no-op; ProcessContainer.js:89 checks `process.env.gid` but sets `pm2_env.gid` (setgid skipped whenever gid absent from env, e.g. numeric gid never exported)
- **Security smells**: `God.getReport` returns the daemon's full `process.env` over RPC (secrets leak to any RPC client); ForkMode dumps every scalar pm2_env key into the child's environment (internal paths/config leak into user process env, visible in /proc/PID/environ); daemon-wide `console.*` monkeypatch (`Utility.overrideConsole`) — rewrite must not replicate; setuid ordering OK (logs opened post-setuid) but pid file written pre-setuid in cluster wrapper
- **Portability traps**: TreeKill win32 `taskkill /T /F` ignores the requested signal — every "graceful" stop on Windows is a force-kill of the tree; default `KILL_SIGNAL=SIGINT` undeliverable on Windows; `ps -e -o pid=,ppid=` fine on macOS/Linux/BSD but snapshot races new children; `detached:true` on Windows allocates a new console group (windowsHide papering over it); chokidar fsevents (macOS) vs inotify limits — `notify` inherits same inotify-watch-count concerns, document `fs.inotify.max_user_watches`
- **Vendored deps, licensing**: `modules/` carries vendored pm2-io-bpm, pm2-io-agent, vizion, pm2-axon, pm2-axon-rpc, fclone — none have package.json license fields (vizion & pm2-io-agent ship LICENSE files); parent project AGPL-3.0 — a Rust rewrite distributing behavior derived from these must audit each vendored tree's actual license before porting logic (pm2-io-* were historically proprietary-ish Keymetrics code; treat as AGPL-tainted until verified)
- **Bun seams**: `cst.IS_BUN` checks scattered through God.js (500ms fake-online timer, clearTimeout in 4 handlers) — fragile timing hack, would vanish in Rust anyway; ProcessContainerBun is a ~200-line copy-paste divergence risk in JS, evidence for single-spawn-path design
- **Oddities**: `next_id` resets to 0 when clusters_db empties (pm_id reuse across app generations — breaks external systems keying on pm_id); `_old_<id>` string keys mixed with numeric keys in one map, filtered by `isNaN` checks in three places; `restart_task` timer hidden via `Object.defineProperty` non-enumerable to survive JSON serialization of pm2_env — symptom of state+config living in one bag (Rust: separate `ProcessConfig` from `RuntimeState`); duplicated message-relay code between ClusterMode/ForkMode with a comment begging to keep them in sync
